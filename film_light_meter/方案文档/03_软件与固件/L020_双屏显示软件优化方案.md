# L020 小 SRAM 下的双屏显示软件优化方案

| 项目 | 内容 |
| --- | --- |
| 项目 | 胶片相机测光板（验证板） |
| 版本 | v1.0 |
| 日期 | 2026-11-19 |
| 适用主控 | PY32L020F15P7（3KB SRAM / 24KB Flash） |
| 目标屏 | 0.97 寸 GDEM0097T61（184×88，2024B）、1.22 寸 GDEM0122T61（192×176，4224B）、1.54 寸 GDEY0154D67（200×200，5000B） |
| 目的 | 在不换 F030、不改硬件的前提下，让 L020 支持 1.54/1.22 屏，保住 1.5µA Stop 低功耗 |
| 关联文档 | `../04_评审与验证/胶片测光板_功能闭环确认.md` |

## 1. 问题

按单色 1bit 帧缓冲计算：

| 屏 | 分辨率 | 帧缓冲 |
| --- | --- | --- |
| 0.97 寸 | 184×88 | 2024B |
| 1.22 寸 | 192×176 | 4224B |
| 1.54 寸 | 200×200 | 5000B |

L020 只有 3KB SRAM：

- 1.54 和 1.22 都超过 3KB，开整屏帧缓冲不可能。
- 0.97 的 2024B 能塞下，但只剩约 1KB 给栈、字库和 UI 状态，余量很小。
- 换 F030 可以解决 SRAM，但 Stop 电流从 1.5µA 升到 4.5µA，整机从约 9.3µA 推到 12–14µA，续航从约 2.5 年降到约 2 年。

本方案的目标是：**不把整屏帧缓冲放在 MCU 里，而是把屏自己的显示 RAM 当帧缓冲，MCU 只做条带或窗口渲染。**

## 2. 核心思路

1. 墨水屏控制器（SSD1680/SSD1681）内部有显示 RAM，容量就是整屏的 2024B/4224B/5000B。
2. MCU 只保留一个 200×8 或 200×16 的条带缓冲，按条带生成像素，通过 SPI 写进屏 RAM。
3. 全刷时把所有条带写完，发全刷命令。
4. 局刷时只计算变化的矩形窗口，重绘该窗口，写进屏 RAM，发局部刷新命令。
5. UI 用显示列表（文字、图标、数值、进度条）描述，不存整屏位图；字库和图标放 Flash。

这样 MCU 的 SRAM 占用从 2024–5000B 降到 200–400B，1.54/1.22 在 L020 上也能跑。

## 3. 方案对比

| 方案 | 做法 | MCU SRAM 占用 | 优点 | 代价 |
| --- | --- | --- | --- | --- |
| A. 条带渲染 | 一次渲染 200×8 或 200×16 的横条，写进屏 RAM，逐条刷完 | 200–400B | 不改硬件，L020 能跑 1.54/1.22 | 代码复杂，UI 不能用整屏位图 |
| B. 显示列表 + 脏区域 | UI 存成文字/图标/数值模型，只重绘变化的矩形窗口 | 100–300B | 局部刷新快，功耗低 | 需要把 UI 改成元素模型 |
| C. RLE 压缩帧缓冲 | 5000B 整屏压缩到 SRAM，按条带解压 | 0.5–2KB | 能保留整屏位图思路 | 解压代码和 CPU 开销，复杂图像压缩率低 |
| D. 外部 FRAM / I2C | 现有 I2C 总线挂 FRAM，帧存外部 | 0 | 容量大，掉电不丢 | 硬件改动，400kHz 写一帧约 100ms |
| E. 0.97 全缓冲 + 1.54 条带 | 0.97 保留 2024B 全缓冲，1.54/1.22 走条带 | 2024B 或 200B | 0.97 代码简单 | 两套路径，代码分支多 |

推荐 **A + B**：条带渲染负责把像素写进屏，显示列表和脏区域负责决定写哪一块。C 作为需要整屏位图时的备选，D 只在必须存整屏图像时考虑。

## 4. 推荐方案 A + B

### 4.1 条带渲染

| 屏 | 条带尺寸 | 单色条带 | 四灰条带 |
| --- | --- | --- | --- |
| 1.54 寸 | 200×8 | 200B | 400B |
| 1.54 寸 | 200×16 | 400B | 800B |
| 1.22 寸 | 192×8 | 192B | 384B |
| 0.97 寸 | 184×8 | 184B | 368B |

屏内 RAM 仍是完整的 5000B/4224B/2024B，MCU 不需要再存一份。

SPI 时序估算：

- 2MHz 下 5000B 约 40ms，4224B 约 34ms，2024B 约 16ms。
- 墨水屏本身全刷 1.5–2s，条带渲染和 SPI 写入的开销可以忽略。
- 可以把 SPI 提高到 4–8MHz，进一步缩短写入时间；先按 2MHz 验证信号完整性。

### 4.2 显示列表与脏区域

UI 不存像素，存元素：

- 文字：内容、位置、字体、对齐方式。
- 图标：图标 ID、位置。
- 数值：光圈、快门、ISO、EV、电量、模式。
- 进度条/刻度：起止位置、当前值。

每个元素有 `draw(x, y, w, h, buf)` 或 `render_stripe(y, h, buf)`，从 Flash 取字模/图标。

脏区域跟踪：

- 修改某个元素时，把它的包围盒并入 dirty box。
- 局刷窗口就是 dirty box，按窗口生成像素，写屏 RAM，发局部刷新。
- 两个元素的脏区域重叠时合并成一个矩形，减少刷新次数。
- 每 20–50 次局刷插一次全刷清残影，全刷也走条带。

### 4.3 SRAM 预算

| 项 | 占用 |
| --- | --- |
| 条带缓冲 200×8 单色 | 200B |
| 条带缓冲 200×8 四灰 | 400B |
| UI 模型（数值、标签、布局） | 100–200B |
| 字库/图标缓存 | 256–512B |
| 栈 | 512B–1KB |
| 合计 | 约 1.2–2KB |

3KB 够用，剩下留给传感器数据、I2C 缓冲和协议状态。

如果保留 0.97 的 2024B 全缓冲，剩余约 1KB，仍然能跑，但条带路径更省。建议统一走条带，减少两套代码。

### 4.4 Flash 预算

L020 有 24KB Flash，需要放：

- 条带渲染器、窗口命令、局部刷新流程。
- 两套字库（8×16、12×24）和图标。
- 三款屏的初始化序列和 LUT。
- UI 模型和业务逻辑。
- I2C 传感器驱动、编码器、低功耗状态机。

24KB 可能接近上限。先编译看代码大小；如果 Flash 先溢出，换 F030/F003 的 64KB，但那时 SRAM 已经不是换芯片的理由。

## 5. 实现步骤

### 5.1 屏驱动接口

```c
void epd_set_window(uint16_t x, uint16_t y, uint16_t w, uint16_t h);
void epd_write_window(const uint8_t *buf, uint32_t len);
void epd_full_update(void);
void epd_partial_update(uint16_t x, uint16_t y, uint16_t w, uint16_t h);
```

### 5.2 全刷

```c
for (uint16_t y = 0; y < EPD_H; y += STRIPE_H) {
    ui_render_stripe(y, STRIPE_H, stripe_buf);
    epd_set_window(0, y, EPD_W, STRIPE_H);
    epd_write_window(stripe_buf, EPD_W * STRIPE_H / 8);
}
epd_full_update();
```

### 5.3 局刷

```c
dirty_box_t box = ui_take_dirty();
if (box.w && box.h) {
    ui_render_window(box, stripe_buf);
    epd_set_window(box.x, box.y, box.w, box.h);
    epd_write_window(stripe_buf, box.w * box.h / 8);
    epd_partial_update(box.x, box.y, box.w, box.h);
}
```

### 5.4 残影管理

- 维护局刷计数，达到 20–50 次后插入一次全刷。
- 全刷走条带，不影响 SRAM。
- 如果某块区域残影明显，优先对该区域做一次全刷窗口。

## 6. 四灰阶

1.54 的 4 灰是 2bit/像素，整屏 10000B。条带 200×8 四灰是 400B，可以流式写。

需要确认：

- SSD1681 的 4 灰局部刷新支持范围。如果只支持整屏 4 灰刷新，就整屏走条带，不用局刷。
- 4 灰 LUT 和刷新序列与单色不同，初始化代码要分开。
- 4 灰整屏刷新更慢，残影管理策略要调整。

如果 UI 主要是文字和图标，单色 1bit 就够；4 灰只用于图标/图片，按窗口或整屏刷新。

## 7. 限制与风险

- **UI 不能是整屏位图。** 显示列表是前提；如果坚持整屏位图，只能用 RLE 压缩或外部 FRAM。
- **局刷残影。** 按 20–50 次局刷插全刷；全刷走条带。
- **Flash 24KB 是另一个约束。** 条带渲染器、两套字库、三款屏的 LUT 可能让 Flash 接近上限；先编译测量。
- **4 灰局部刷新支持有限。** 可能只能整屏刷新；整屏也用条带加载。
- **面板 RAM 是唯一帧缓冲。** MCU 不保存旧帧，局刷窗口必须能完整重绘；半透明叠加、复杂抗锯齿不适合。
- **SPI 信号完整性。** 先按 2MHz 验证，双屏座和跳线会引入 stub；如果波形差，降速或改走线。

## 8. 原型与验收

先做一个最小原型，不接完整 UI：

1. 1.54 屏，200×8 条带缓冲。
2. 显示固定背景加两个动态数字（例如快门和 ISO）。
3. 验证全刷、局刷窗口、每 20 次局刷后的全刷。
4. 测量：
   - 编译后 `.bss` 和栈水印，确认 SRAM 余量。
   - Flash 占用，确认 24KB 是否够。
   - 局刷时间、全刷时间、残影程度。
   - 2MHz 和 4MHz SPI 下的波形和稳定性。

验收标准：

- 1.54 和 1.22 都能全刷、局刷，残影在可接受范围。
- SRAM 余量 ≥ 512B，Flash 余量 ≥ 2KB。
- 局刷窗口不闪屏，数字变化无明显拖影。
- 0.97 仍能正常显示，三款屏共用一套 UI 模型。

如果原型通过，L020 可以继续用，Stop 保持 1.5µA。如果 Flash 先溢出，或 UI 需要整屏 4 灰图片，再考虑 F030/F003 的 64KB Flash + 8KB SRAM，届时 SRAM 只是顺带的好处。

## 9. 结论

- 软件层可以解决 L020 的 3KB SRAM 限制，不需要换 F030。
- 推荐条带渲染 + 显示列表 + 脏区域局刷，SRAM 占用约 1.2–2KB。
- 真正的约束会从 SRAM 转到 Flash 和 UI 复杂度；先做原型测量，再决定是否换芯片。
- 如果只做文字/图标/数值的测光表 UI，L020 足够；如果要整屏 4 灰图片或复杂图形，F030/F003 更省事。
