## 1. 现在是什么状态

代码骨架已全部落盘，**2026-11-17 已编译通过**（`idf.py build`，0 error；只剩
`app_console.c` 的 `-Wmissing-field-initializers` 警告，不影响运行）。

板子四路灯珠都已装：**红 CH1、绿 CH2、蓝 CH3、红外 CH4**。**本版上电四路全部点亮（各 15% / 50.0mA）**。绿色/蓝色/红外通道的焊桥跳线分别是 **JP2/JP3/JP4**，都必须短接。

红外光肉眼不可见，不能靠"看灯亮"判断。验证方式是光强板 BPW34S → OPA333 跨阻（47kΩ）→ ADS1110，固件 `meas ir` 读出的光电流应从暗底明显上升；手机摄像头通常也能看到红外光点。

## 3. 编译、烧写、看日志

工程自带脚本（IDF v5.3.3，装在 `D:\esp`）：

```bat
build.cmd                  :: 编译
flash.cmd COM15            :: 烧到 COM15（不传参数默认 COM6）
```

手动等价命令：

```bat
idf.py -p COM15 flash monitor
```

用 VS Code 的乐鑫扩展时注意三点：

1. 用**工程根目录**打开，不要用上级目录，否则扩展找不到 `CMakeLists.txt`
2. 扩展里选的 IDF 必须是 `D:\esp\v5.3.3\esp-idf`，和 `build.cmd` 同一套，否则 `sdkconfig` 会被另一版 IDF 重写
3. 目标芯片 `esp32c2`，Flash 4MB，**串口监视 74880**（不是 115200，原因见 §3.1）

`build.cmd` 末尾有 `pause`，命令行调用时加 `< nul`，否则会卡住。

### 3.1 为什么是 74880 而不是 115200

`CONFIG_ESP_CONSOLE_UART_BAUDRATE` 在 Kconfig 里**不是可提示项**：只有选了
`ESP_CONSOLE_UART_CUSTOM` 才会让你填。默认走 `ESP_CONSOLE_UART_DEFAULT`，值由规则决定：

```kconfig
default 74880 if (IDF_TARGET_ESP32C2 && XTAL_FREQ_26)
default 115200
```

本板为了 26MHz 晶振设了 `XTAL_FREQ_26=y`，所以实际就是 **74880**。手改
`sdkconfig` 或 `sdkconfig.defaults` 都会被 `kconfgen` 覆盖回去，别在这上面浪费时间。
真要 115200 就得切自定义 console 配置，没有必要。

## 4. 硬件事实（写死在 `light_cfg.h`）

| 项 | 值 |
|---|---|
| I2C | GPIO0=SDA，GPIO1=SCL，**100kHz**（400kHz 实测丢数据，见 §8），7 位地址 |
| 上拉 | 主板 4.7k，软件只开内部弱上拉，不要重复加强 |
| MCP4728 | 0x60，VREF=VDD(3.3V)，LDAC# 接地 |
| ADS1110 | 0x48，连续 15SPS，增益 1，LSB 62.5µV |
| AL8862 | **R_SET = 0.30Ω → I=0.1V/0.30Ω=333.3mA**；CTRL 0.4~2.5V 对应 10%~100%（33.3mA~333.3mA）；<0.3V 关断 |
| 跨阻 | 47kΩ，1µA 光电流 ≈ 47mV |
| DAC 满码 | 3102（2.5V） |

## 5. 上电行为

1. `mcp4728_set_all(0,0,0,0)` 先把四路关断（MCP4728 上电会直接输出 EEPROM 旧值，不关会亮）
2. 配 ADS1110 为连续 15SPS，等 100ms
3. 8 次平均读暗底存 `s_dark`
4. 从 NVS 加载标定，没有就用未标定状态
5. **四路全部点亮**：`light_set_ma(CH_R/G/B/IR, LIGHT_BOOT_*_MA)`，
   四路默认都是 50.0mA = 15%。红外不可见，需要时用 `meas ir` 或 `vin` 确认光路。
   当前板子只焊了红灯，4 颗串联在 CH1，只能一起亮；设
   `LIGHT_BOOT_R_MA=0` 可关掉上电点灯
6. 起控制台，进入 1s 循环

## 6. 控制台命令

串口 **74880**，提示符 `light>`。

| 命令 | 作用 |
|---|---|
| `scan` | 扫总线，正常应看到 0x60 和 0x48 |
| `off` | 四路全关 |
| `set r 50` | 红灯设 50mA（ch 可写 0-3 或 r/g/b/ir） |
| `code r 1655` | 直接给 DAC 码，用于绕过换算量 CTRL 电压 |
| `meas r` | 测红灯光电流；`meas` 不带参数四路轮测 |
| `tgt r 2.5` | 设红灯闭环目标 2.5µA |
| `loop on` | 开闭环（1s 一拍，四路轮转） |
| `mode a` / `mode b` | a=分时（默认，能分通道闭环），b=同时 |
| `cal` / `calsave` | 四路 50% 标定 / 写入 NVS |
| `status` | 打印 code、CTRL 电压、电流、目标、增益、故障标志 |
| `vin` | 读一次 ADS1110 VIN+ 的原始电压（不扣暗底），诊断光强板 |
| `mon on` / `mon off` | 每 100ms 连续打印 `[VIN] x.xxxx V`，用于手电/手指测试 |

## 7. 建议的调试顺序

| 步 | 操作 | 判据 |
|---|---|---|
| 1 | 上电看日志 | 出现 `scan: N device(s)`，`dac=1 adc=1` |
| 2 | `scan` | 0x60、0x48 都有 ACK |
| 3 | `off`，`meas` | 四路光电流都接近 0（暗底已扣） |
| 4 | `set r 50` | 万用表量 MCP4728 CH1 输出 ≈**0.52V**，红灯亮（50mA 是 333.3mA 的 15%，CTRL 从 0.4V 起算） |
| 5 | `code r 497` / `code r 3102` | CTRL 分别约 0.4V / 2.5V，电流约 33.3mA / 333.3mA |
| 6 | `meas r` | 读数随亮度单调变化，不饱和 |
| 7 | `cal` + `calsave`，断电重启 | 标定值还在（`status` 看 gain） |
| 8 | `tgt r 2.5` + `loop on` | code 收敛后不再大幅摆动 |

## 8. 几个已经踩过/修正的点

**MCP4728 命令字**：原始文档写 `0x40 | ch`，通道号落在 bit1:0；手册 5.6.3 里通道在 bit2:1，正确写法是 `0x40 | ((ch & 3) << 1)`。按文档写的话只有红路对，绿会重复写红、蓝会盖到绿的位置。代码已按手册改，上板第 4 步能直接验出来。

**0.3~0.4V 死区**：原始文档的 `code_for_current()` 在 0~33.3mA 会算出 0.1~0.4V，而 AL8862 低于 0.3V 关断、0.3~0.4V 手册没定义。现在统一钳到 0.4V（33.3mA），需要真正关断就传 0。

**ADS1110 配置字**：0x0C = 连续/15SPS/增益1，0x1C 单次、0x9C 启动，已和 `fl1s_KC_driver/HDL/ads1110` 的实现逐位核对过。

**分时测量会关灯**：`light_measure_ua()` 在分时模式下会临时关掉其他三路，测完恢复。曝光期间不要调用，否则拍出来的图会被吞掉三色。

**四路都已装**：绿色对应 MCP4728 CH2、AL8862 U5、焊桥 JP2、R2（0.30Ω）；
蓝色对应 CH3、U6、JP3、R3（0.30Ω）；红外对应 CH4、U7、JP4、R4（0.30Ω），
灯珠 LED_IR1~IR4，Vf≈6.2V。红外不可见，验证靠 `meas ir` 的光电流读数。

**`esp_console` 是头文件名，组件名是 `console`**：`main/CMakeLists.txt` 的
`PRIV_REQUIRES` 里必须写 `console`，写 `esp_console` 会在 CMake 配置阶段报
`Failed to resolve component 'esp_console'`。IDF 5.3.3 的组件目录是
`components/console`，头文件才是 `esp_console.h`。

**VS Code 扩展的 `idf.buildPath` 必须指回本工程**：这个工程的
`.vscode/settings.json` 曾指向 `ESP8684_Empty_Project\build`，导致
`build/CMakeCache.txt` 是用另一个工程的源目录生成的，构建报
`CMakeCache.txt ... is different than the directory ... where CMakeCache.txt was created`。
已改为 `${workspaceFolder}/build`；再遇到同类错误就删掉 `build/` 重配。

**串口 74880，不是 115200**：见 §3.1。手改 sdkconfig 无效，kconfgen 会覆盖。

**I2C 必须用 100kHz**：400kHz 下实测 ADS1110 读操作大量 NACK、MCP4728 写入
偶发丢数据（表现为 `code r 3102` 写成功但 CH1 仍是上一档 0.514V）。降到 100kHz
后同一块板子零 NACK、DAC 输出正常。`light_cfg.h` 里已经改成 100000，不要调回去。

**JP1 是常开焊桥，必须短接**：PCB 上网表为
`JP1 pad1=/CH1 (TP1、U4 pin8 CTRL)`、`pad2=/DAC_with_external_Vref/CH1 (U3 VOUTA)`。
不短接时 DAC 与 AL8862 完全断开，表现为 I2C 写入成功、CTRL 一直是 0V、灯不亮。

**R_SET 是位号 R1，本板实际装 0.30Ω**：原理图值标为 "R30"（0.30Ω），现在板上也换成了 0.30Ω，所以固件里 `I_FULL_MA=333.3mA`。换板/换电阻时必须同步改 `light_cfg.h`。R1 串在
`+24V → LED 串 → L1 → U4 SW` 之间，装错/虚焊会导致整路无电流。实测这块板曾经
就是限流电阻设错导致不亮，换对后整条链路正常。

**10%（33.3mA）这一档灯不亮**：实测 AL8862 在最小调光档起不来，固件上电默认取
15%（50mA）。要更暗先确认驱动能在该档稳定起振，不要直接写 10%。

**ADS1110 上电偶发不应答**：复位后有时 config write NACK，导致 `sensor_fault=1`、
所有 `meas` 都返回 `ESP_ERR_INVALID_STATE`。现在 `light_init()` 会重试 5 次
（每次间隔 100ms），并且 `light_measure_ua()` 在 sensor_fault 时还会自动恢复一次
（灭灯、重初始化、重采暗底、恢复原亮度）。如果仍然失败，先查光强板供电和排线。

**MCP4728 上电先发 General Call Wake-Up**：`[0x00, 0x09]`，清掉四路 power-down 位。
否则器件可能从 EEPROM 带着 PD 位起来，I2C 写照样 ACK 但输出脚是关断的。
实现见 `drv_mcp4728.c` 的 `mcp4728_wakeup()`，`light_init()` 里先调它。

## 10. 排障

| 现象 | 先查 |
|---|---|
| `scan` 只有 1 个器件 | 排线、J2/J4 与 J3 的 1-4 脚线序、4.7k 上拉 |
| `set` 报 i2c write failed | 总线被拉死，断电重上；仍不行降速到 100kHz 再试 |
| 灯不亮但 CTRL 电压对 | 看 AL8862 的 EN、LED 串、R_SET |
| `meas` 恒 0 | 光强板未接、BPW34S 方向、OPA333 供电、ADS1110 地址脚 |
| `meas` 报饱和 | 电流太大或跨阻太大；先把电流降到 10% 再测 |
| 控制台无响应 | 波特率 **74880**；串口被其他程序占用；`flash.cmd` 后要 `monitor` 才能输入 |
